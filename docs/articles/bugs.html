从 V3 到 V4.7.5：真实故障与修复记录

这份记录来自本次连续测试。它保留失败的假设，区分“代码里确实存在的缺口”和“已经证实的实际故障原因”。不把一次成功、模拟检查或普通网页警告当作全部问题已解决的证据。

三、题型、答案格式与本地服务

  • 判断题漏识别。 页面选项可能没有 A/B，而是正确/错误、√/×，顺序也可能反过来。V4.5 根据实际元素含义归一化，再映射回 DOM，不把第一项永远当作“正确”。
  • 总题量 40，之前只读到 30。 移除错误的总量限制；完整核对整套题后，每批 10 题请求，所有批次验证后才操作页面。任何批失败都不会继续提交部分答案。
  • 填空有第一空、第二空。 V4.6 引入多空模型，将输入位置保留为编号标记，答案按字符串数组返回；空数、长度、非空性与填写结果都需要核对。富文本编辑器使用已有实例 API。
  • “题目格式不正确”与 502。 增加请求阶段、服务版本和字段级错误；本地校验失败使用 422，上游调用失败使用 502。发现并修复 UTF-8 网络分块解码缺口，但没有证据断言它就是当时 502 的唯一原因。
  • 磁盘已更新，服务仍是旧版本。 实际健康检查曾只返回 {"ok":true}，说明还运行着旧进程。V4.6.1 起增加协议和服务元信息，V4.7.1 在输入密钥前先绑定端口，明确区分启动失败和新服务成功。

四、部署方式的问题

调试器暂停

页面执行 debugger 语句时，如果开发者工具开着，整个网页和自动脚本都会暂停。“抛出异常时暂停”的勾选与“停用断点”是不同控制。反复刷新或延长脚本等待时间没有解决这个问题。

V4.7.0 增加油猴入口和页面状态框，日常运行不再需要保持 F12 打开；完整导航由油猴重新启动。这个改动没有删除网页的 debugger，也没有修改浏览器安全策略。

辅助窗口跨域

旧控制台入口通过小窗口重注入。新页面不可被它同源访问时，读取 location.href 会报错。V4.7.1 改为等待可访问页面，并明确建议跨域导航使用油猴；没有声称绕过同源规则。

油猴“此脚本还未执行”

先核对 URL、元信息、扩展权限和开关，再用只显示绿色条的最小脚本隔离问题。后来主脚本状态框出现，证明已经开始执行；不能把最初没有 UI 的情况继续当成 API Key 或答题逻辑错误。

连接令牌不匹配

每次服务启动都会生成新令牌。油猴中存的是安装时的副本，不会跟随磁盘文件自动更新。正确顺序是：服务启动成功 → 复制该目录生成文件 → 替换油猴全文 → 保存 → 刷新。为了“修复令牌”再次重启服务，反而会再次换令牌。

五、最后一批填空题：为什么改了几次

1. V4.7.2：先让失败可解释。 原实现静默跳过不符合条件的题目，用户只能看到 35/40。加入识题诊断按钮，同时修复标签含空格和被多个 span 拆开的缺口。此时还不知道漏掉的到底是什么题。 2. V4.7.3：补齐容器与格式覆盖。 诊断显示有填空找不到输入框。修复固定 9 层上溯限制，支持 plaintext-only 可编辑区，并增加结构诊断。这是代码中的真实缺口，但没有解决全部实际漏题；不能把它写成最终根因。 3. 实际诊断定位到 16、18、20、21、25。 这些题各有两到三个 iframe 与 textarea，全部被可见性筛选排除。用户点击后数量仍未增加，因此“只需要点击激活”没有被验证为解决方案。 4. 元素面板截图确认 UEditor。 实际可输入区域位于 iframe#ueditor_0 内，body.view/p 是编辑区域，下面的 textarea 是相关同步结构。由此改为优先匹配已有编辑器实例，而非仅依赖 iframe 的几何可见性。 5. V4.7.4：题量齐了，但仍有 11 空等待。 实例、body 和空位都找到了，新的严格校验却只接受布尔 true。模拟 fixture 也默认 true，因此检查通过，却漏掉真实库使用数字的情况。 6. V4.7.5：修复数字 1 的就绪标记。 官方 UEditor 核心赋值 isReady=1。现在接受 1 与 true，0/false 仍阻止答题；将模拟 UEditor 的默认值也改为官方数字 1，并保留未知标记的诊断。

最后一项是上一版兼容判断错误，不是用户操作问题。完成 V4.7.5 后，本次实际课程收到“可以顺畅运行”的反馈。

六、这段调试过程教会了什么

  • 先缩小故障层级。 扩展是否执行、本地服务是否连接、题目是否齐全、编辑器是否就绪、模型是否返回、填写是否保存，是不同的问题。
  • 用可观察证据代替猜测。 状态框和脱敏诊断减少了依赖 Console 的次数；数值、字段状态和 DOM 元素截图比一条笼统报错更有用。
  • 真实库行为必须进入测试。 isReady 的 true/1 问题说明 fixture 不能只反映自己希望的接口。
  • 保持完整性保护。 少题、少空、字段变化、实例被替换、同步失败时停止；放宽总题量只会掩盖问题。
  • 不要夸大验证结论。 模拟检查、源码核对与实际页面反馈各自覆盖不同范围；当前代码仍需随平台变化维护。
